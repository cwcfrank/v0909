Vibe Coding 實作課 — 操作包

靜宜大學 2026/09/09 ｜ 講師：圈圈 ｜ 這頁不用背，照著抄。卡住舉手。
今天下課，你會有：一個自己做的網站，和一個可以傳給別人的公開網址。

今天最重要的觀念，先講

新手最常做的事：跟 AI 說「幫我做一個很棒的網站」，然後拿到一個不是自己要的東西。

老手做的事：先讓 AI 拷問自己，把腦子裡沒想清楚的地方一次問出來，確認共識了才動手寫。今天第一步就是這個。

第 0 步 開工前的三個動作4-8 分 ｜ 跟著我一起做，不要往下跑

  1. 打開 Cursor，登入（email 註冊就好，免費、不用信用卡）
  2. 左上 File → Open Folder → 選桌面 → 新建一個資料夾 → 選它 → Open
    ⚠️ 資料夾名字用英文小寫、用減號連接，例如 water-tracker。 這個名字之後會變成你網址的一部分，用中文或有空格，等一下部署會壞。
  3. 認識三個地方，今天只會用到這三個，其他按鈕一律不要碰：
A Agent 對話框在右邊。你所有的話都對它說。
B 瀏覽器預覽index.html 按右鍵 → Open with Live Server
C Source Control在左邊工具列，等一下推上 GitHub 用。

第 1 步 讓 AI 拷問你8-16 分

打開 Cursor 的 Agent 對話框，按下面的按鈕複製，貼進去，第一行填你想做的題目：

我想做一個 ______________ 的網頁小工具。

在你寫任何程式之前，請先拷問我，把我沒講清楚的地方問出來：
- 一次最多問我 5 個問題，一題一行、有編號
- 每一題都要附上「你建議的答案」和一句話理由
- 問完就停下來等我回答，不要自己假設、不要先寫程式
- 我回答後如果還有沒問清楚的，再問我第二輪（最多兩輪）

兩輪之後，請把結論整理成下面這樣給我，然後才開始寫程式：
【我要做的東西】一句話
【功能清單】三項，動詞開頭
【驗收方式】三個我可以自己動手確認的步驟
【我們決定不做的事】

技術限制（這些不用問我，直接照做）：
單一 index.html 檔案、不要用需要安裝的套件、不連資料庫、不需要登入功能。

怎麼回答它的問題

不知道怎麼答就寫「照你的建議」。也可以混著答：「1 照你的建議，2 我要 A，3 這個不用做」。

你是老闆，AI 是來問清楚需求的工程師。它問你問題不是它笨，是它在避免做白工。

⚠️ 如果它問到第三輪還在問：直接說「不要再問了，照你的建議整理成規格然後開始寫」。

把它整理的規格抄到學習單第 ① 格——尤其是【驗收方式】那三個步驟，那是你等一下用來抓 AI 說謊的武器。

備用：AI 一直不問、或直接開始寫程式（點開）

自己把這三格填完貼給它：

  • 目的（一句話）：我想做一個 ＿＿＿＿ 的網頁。
  • 三個功能：1. 可以＿＿ 2. 可以＿＿ 3. 可以＿＿
  • 三個驗收動作：我做＿＿會看到＿＿（寫三個）

範例（喝水紀錄）：功能＝按一下加一杯／顯示今天總共幾杯／可以歸零； 驗收＝按 3 次數字變 3／關掉再打開數字還在／按歸零變 0。

第 2 步 確認規格，讓它開始寫16-24 分

AI 給你【功能清單】和【驗收方式】之後，看一眼：有沒有你根本不想要的功能（說「第 2 項不用做」）？ 有沒有漏掉你最在意的事（現在補，比寫完再改便宜十倍）？

規格沒問題，請開始寫。寫完後告訴我怎麼一步一步測試上面的驗收方式。

第 3 步 看成果

在左邊檔案列表的 index.html 上按右鍵 → Open with Live Server → 瀏覽器就會打開你的網頁。

沒有這個選項的人：打開桌面上你的資料夾，直接用滑鼠雙擊 index.html，一樣會用瀏覽器打開。

打開是一片空白 → 跟 Agent 說：
「網頁打開是空白的，請檢查 index.html 是否完整，並確認所有程式碼都寫在這一個檔案裡。」

第 4 步 改兩次，一次只改一件事24-34 分

規則：一次只講一件事，改完先驗收，成功了才改下一件。 一次丟三件事給 AI，壞掉的時候你不會知道是哪一句造成的。

講法固定成這個格式：

請把 ______ 改成 ______。改完告訴我怎麼確認。

常用的第一次修改（挑一個）

  • 請幫每一筆加上刪除按鈕，按下去那一筆就消失。
  • 請把數字改大一點，手機上也看得清楚。
  • 請把已完成的項目變成灰色，並移到最下面。

常用的第二次修改（挑一個）

  • 請加上資料儲存，關掉瀏覽器重新打開後，我的資料還在。
  • 請在最上面顯示今天的日期。
  • 請把配色換成深色背景、亮色文字。

第 5 步 ★ 驗收儀式34-44 分 ｜ 全班一起做，不要跳過

當 AI 說「我已經完成並測試過了」——

這句話永遠不能相信。AI 沒有你的瀏覽器，它從來沒有點過你的網頁一下。

1. 按一下有反應嗎？該出現的東西出現了嗎？
2. 按 F5重新整理後，剛剛輸入的東西還在嗎？（最常出事）
3. 拉窄視窗縮到手機寬度，有跑版嗎？按鈕被切掉了嗎？

有問題就把「壞掉的樣子」講給它聽，不要只說「壞了」

✅ 我按了 3 次，數字有變成 3。但我按 F5 重新整理後數字變回 0 了。我要的是重新整理後還是 3。
❌ 不會動，修一下

公式：我做了什麼 → 我看到什麼 → 我期望看到什麼。三段都給它。

第 6 步 推上 GitHub（第一個 commit）44-58 分

  1. 點 Cursor 左邊工具列的 Source Control（分支圖案）
  2. 上面的訊息框輸入一句話說明你做了什麼，例如「第一版 喝水紀錄網頁」
  3. 按 Commit（問你要不要 Stage All Changes，選 Yes）
  4. 出現 Publish Branch → 按下去 → 選 public repository （一定要選 public，選 private 之後網址不會公開）
  5. 會跳出瀏覽器要你授權 GitHub → 用課前註冊的帳號登入 → Authorize
  6. 打開 github.com，你會看到你的專案在上面

⚠️ 卡在授權的人：舉手，不要一直重按。

第 7 步 拿到你的公開網址58-70 分

  1. 在 github.com 打開你剛剛的專案
  2. 上方 Settings → 左邊選單往下找 Pages
  3. Source 選 Deploy from a branch
  4. Branch 選 main、資料夾選 / (root) → 按 Save
  5. 等 1-2 分鐘，重新整理這頁，最上面會出現你的網址：
https://你的帳號名稱.github.io/你的資料夾名稱/

打開它確認網站真的活著，然後把網址貼到班級展示牆（老師會給連結）。

打開是空白頁：等 2 分鐘再重新整理。還是空白就舉手——八成是選了 private， 或首頁檔案不叫 index.html。

第 8 步 再改一件事（第二個 commit，看得到歷史）70-80 分

  1. 回 Cursor，跟 Agent 說第 4 步的「第二次修改」那句
  2. 驗收（第 5 步的三個動作）
  3. Source Control → 輸入訊息 → Commit → Push
  4. 回 github.com 你的專案 → 點上方的 Commits → 你會看到兩次 commit
  5. 等 1-2 分鐘，重新整理你的公開網址 → 網站自己更新了

這就是版本控制：每次改動都留下記錄，隨時知道什麼時候改了什麼，也隨時回得去。

卡住時的三個急救

1. 網頁打不開／一片空白
「網頁打開是空白的，請檢查 index.html 是否完整，並確認所有程式碼都寫在這一個檔案裡。」

2. 改一次就整個壞掉
「請退回上一個可以正常運作的版本，然後只做這一件事：______」

3. AI 一直說完成但就是不對
換一種說法描述現象，補上「我實際看到什麼」和「我期望看到什麼」，並要求它「先告訴我問題在哪裡，再改」。

下課帶走三句話

  1. 動手之前，先讓 AI 把你沒想清楚的地方問出來。講清楚要什麼，比會不會寫程式重要。
  2. AI 說完成不等於完成，驗收是你的工作。按一下、按 F5、拉窄視窗。
  3. 一次只改一件事，改完就存一版。壞掉的時候，你才知道是哪一句造成的。
