你說得清楚，AI 就寫得出來

90 分鐘做出一個真的能上網的網站，下課前拿到自己的網址，傳給誰都打得開。 照著圖做，每完成一步打個勾。

🧸 白話說

今天你的角色是屋主，不是工程師。AI 是師傅——它在畫面上的名字叫 Agent（程式開發代理人）：你負責講清楚要什麼、親自驗收， 最後掛上門牌讓大家找得到。接下來每一步都會用這個比喻講一次。

今天要走完的四大段。每一段都有圖，照圖做就好。

今天最重要的一句話 新手叫 AI「做一個很棒的網站」。老手先叫 AI 反過來拷問自己。
開工前

準備

工具搬進來、鑰匙拿到手。這段少一項，後面每一步都會卡。

STEP 0

開工前：裝好、登入、認識兩個地方

8–18 分 ｜ 跟著講師做
🧸 白話說

第一段

需求釐清

把腦中模糊的想法，變成一份 AI 看得懂、你自己也認得出來的規格。

STEP 1 ★

讓 AI 拷問你

實作 60–65 分
🧸 白話說

好師傅不會問「你想要很棒的房子嗎」，他問你要幾房幾廳。先讓 AI 問你，它才不會做出你不要的東西。

它問你，是為了不做白工。

我想做一個 ______________ 的網頁小工具。

在你寫任何程式之前，請先拷問我，把我沒講清楚的地方問出來：
- 一次最多問我 5 個問題，一題一行、有編號
- 每一題都要附上「你建議的答案」和一句話理由
- 問完就停下來等我回答，不要自己假設、不要先寫程式
- 我回答後如果還有沒問清楚的，再問我第二輪（最多兩輪）

兩輪之後，請把結論整理成下面這樣給我，然後才開始寫程式：
【我要做的東西】一句話
【功能清單】三項，動詞開頭
【驗收方式】三個我可以自己動手確認的步驟
【我們決定不做的事】

技術限制（這些不用問我，直接照做）：
單一 index.html 檔案、不要用需要安裝的套件、不連資料庫、不需要登入功能。
它問到第三輪還在問 直接說：「不要再問了，照你的建議整理成規格然後開始寫。」
想先看一個做完的例子？ 有人選了「中午吃什麼的拉霸轉盤」——拷問時 AI 問他「紀錄要記『轉到什麼』還是『真的吃了什麼』」， 他自己完全沒想過這有差。看他的成品 ｜ 想看更誇張的：Minecraft 風格的版本 ｜ 3D 拉霸機（特效版）
還沒想到要做什麼？從這裡挑一個
自我・社交　個人履歷／自我介紹網站・社團宣傳頁・ 追劇進度表・重訓紀錄・遊戲戰績・交換禮物抽籤・紀念日倒數
課業　作業到期倒數・還要考幾分才過・下一堂在哪間教室・ 分組抽籤／點名輪盤・讀書番茄鐘
生活　中午吃什麼拉霸轉盤・宿舍分帳誰欠誰・洗衣機輪班表・ 今天喝幾杯水・機車油耗

今天做不了的 登入註冊、聊天室、抓即時資料（公車、股價）、多人同時編輯。 想做的話：改成自己手動輸入資料的版本就行。

第二段

程式開發

規格確認完，按下去讓 AI 動工。這段你不用寫程式，但要看得懂它在做什麼。

STEP 2

確認規格，按 Proceed 開工

實作 65–68 分
🧸 白話說

設計圖在你手上：不要的劃掉、漏的補上。都對了，按一下「Proceed」，師傅就開始動工。

規格對了就按 Proceed（繼續）——不用再貼任何指令。

還有地方不對？先別按 直接在對話視窗打字說「第 2 項不用做」「再加一個 ______」，等它把規格改好，再按 Proceed。

按下去等 1–2 分鐘，它會自己建立 index.html。 這段時間把它列的 【驗收方式】三步抄到學習單上——下一步就照著做。

第三段

驗收校正

AI 說完成不等於完成。自己動手驗收，找到問題，再一次只改一件事。

STEP 3 ★

看成果，然後自己驗收

實作 68–73 分
🧸 白話說

房子蓋好要親自走進去看一眼，而且水龍頭要自己開。 在 index.html 上點兩下，就是走進去。

用瀏覽器打開就是真的網頁——按鈕、輸入、F5 都能測，跟上線後一樣。

打開是一片空白 在對話視窗跟師傅說：「網頁打開是空白的，請檢查 index.html 是否完整，並確認所有程式碼都寫在這一個檔案裡。」
改完之後怎麼再看一次 師傅改完檔案後，回到已經開著的瀏覽器分頁按 F5 就會更新，不用重新雙擊。

看到畫面了——接下來是今天最重要的兩分鐘：驗收

親手試一次：這就是等一下會發生在你身上的事

迷你網頁：喝水紀錄
今天喝了 0 杯

AI 說：「已完成並測試過，資料會自動儲存。」→ 按幾下「加一杯」，然後按 F5。

✓ 這樣說，它一次就中 我按了 3 次，數字有變 3。但按 F5 後變回 0。我要的是重新整理後還是 3。
✕ 這樣說，它只能猜「不會動，修一下」／「壞了」

公式：我做了什麼 → 我看到什麼 → 我期望看到什麼

STEP 4

一次只改一件事

實作 73–78 分
🧸 白話說

一次只叫師傅改一個地方。同時改三個，壞了你不知道是哪個害的。

改什麼？ 就改你剛剛驗收時發現不對的那一個地方。都沒問題的話，挑一個你最想要的功能—— 但一次只講一件，講完馬上回上一步再驗收一次。
第四段

專案部署

寫一份說明書、推上 GitHub、開啟 Pages，拿到一段誰都打得開的網址。

STEP 5 ★

推上 GitHub，拿到你的公開網址

實作 78–88 分
🧸 白話說

房子蓋好，還要寫一份說明書、搬進展示間、掛上門牌，別人才進得來。 這三件事一次講給 AI 聽。

請幫我把這個專案上線，做三件事：

1. 根據我們前面確認的規格，在專案資料夾裡建立 README.md，內容包含：專案名稱、這個網站在做什麼（一句話）、功能清單、驗收方式、怎麼使用。
2. 把這個資料夾變成 git 專案，做一次 commit（訊息寫「第一版」），推送到我的 GitHub，開一個「Public 公開」的 repository，名稱跟資料夾同名。
3. 開啟 GitHub Pages（Source 選 Deploy from a branch、branch 選 main、資料夾選 /(root)），部署成任何人都能打開的網站。

完成後請直接給我那一段可以公開訪問的網址。
過程中如果需要我登入 GitHub 或按授權，請停下來告訴我要按哪裡。

先組出你的網址（順便檢查資料夾名合不合法）

https://＿＿＿＿.github.io/＿＿＿＿/

打開是空白頁 等 2 分鐘再重整。還是空白就舉手——八成是 repo 選了 private，或檔案不叫 index.html。
加分題

讓你的網站跟別人不一樣

提早做完 or 回家做
🧸 白話說

牆還沒粉刷就先掛水晶燈，只會更亂。先確定網站上線又驗收過，再來裝飾。

你可能已經用到了 Antigravity 常常自己就引入 Three.js 或 GSAP（程式碼最上面有 cdnjs.cloudflare.com 就是）， 那正是下面第 1、2 招。記得驗收——這是從網路上抓的，校網擋掉就壞掉。
三個前提，違反一個就不要加特效 ① 網站已經上線並驗收過（沒有就回 STEP 5）
② 一次只加一招（特效更容易一次改壞）
③ 每加一招 commit 一次（壞了才回得去）
01Three.js — 會動的 3D 背景 最有「哇」的效果

在網頁最底層放一層緩慢飄動的粒子。最容易讓人記住你的網站。

請用 CDN 引入 three.js（不要用 npm、不要拆成多個檔案），在我的網頁最底層加一個 3D 動態背景：緩慢飄動的粒子。

條件：
1. 只能新增背景層，現有的內容與功能完全不要動
2. 背景在內容下面，文字必須維持清楚可讀
3. 手機上自動降低粒子數量，不要讓手機卡住或發燙
4. 如果使用者系統設定了「減少動態效果」，就不要播動畫

改完後告訴我怎麼一步一步確認上面四點。

坑：手機發燙、變慢 → 粒子數設小；校網擋 CDN 會整片黑，記得 F5 驗收。

02GSAP — 進場與滾動動畫 最容易看起來專業

標題和卡片依序滑進來，而不是一次全跳出來。順序感＝「做得很細」。

請用 GSAP 的 CDN 版本，為現有元素加上進場動畫：標題與卡片依序淡入並輕微上移，每個間隔 0.08 秒。

條件：
1. 就算 JS 載入失敗，內容也必須看得到（不要讓元素卡在透明狀態）
2. 每個元素只播一次，不要每次滾動都重播
3. 尊重「減少動態效果」的系統設定
4. 不要改動任何原有的功能

改完後告訴我怎麼驗收這四點。

坑：動畫沒跑成功，內容會永遠透明 → 第 1 條就是在防這個，一定要留。

03Design DNA — 先定設計基因，再改樣式 最省時間

先定一套顏色／字級／圓角／陰影規則，再叫它「只准用這套」。改十次也不會越改越亂。

在改任何樣式之前，先幫我定一套 design DNA，寫成 CSS 變數放在 :root：
主色、輔色、背景色、文字色各一；字級 4 級；圓角 2 種；陰影 2 種；間距用 4 的倍數。

然後把整個網頁改成只使用這些變數，不要留任何寫死的色碼或尺寸。

最後把這套 DNA 列出來給我看，並告訴我改了哪些地方。

坑：AI 會順手改掉你喜歡的顏色 → 它列 DNA 時對一次，不喜歡就叫它換那一個。

04Motion design — 動效要有意義 分辨新手與老手

新手加一堆會動的，老手只讓「使用者做了什麼」有回饋。少而準比多而炫值錢。

請幫我做「互動回饋」而不是裝飾動畫：

1. 按鈕 hover 和按下時要有明顯但輕微的變化（120-180 毫秒）
2. 清單新增一筆時滑入，刪除時淡出
3. 每個動畫都要對應一個使用者動作，不要有無限循環的動畫
4. 所有動畫時間 ≤ 300 毫秒，進場用 ease-out、離場用 ease-in

改完告訴我每個動畫分別對應哪一個動作。

坑：動畫太多會頭暈，展示反而扣分 → 加完自己用一次，覺得煩就砍一半。

05視覺層次（Genjutsu）— 用光影做出「很貴」的質感 不用任何圖檔

純 CSS 做出景深：極淡雜訊、模糊光暈、毛玻璃、兩層陰影、滾動視差。沒有加任何圖片，質感卻完全不同。

請只用 CSS 讓畫面更有層次感，不要使用任何圖片檔：

1. 全頁加一層極淡的雜訊質感
2. 主視覺後方放一顆模糊的漸層光暈
3. 卡片用毛玻璃效果（backdrop-filter）加兩層陰影
4. 滾動時背景和前景速度不同（視差），但手機上關掉視差

條件：文字的對比與可讀性不能變差。改完告訴我怎麼確認文字還是清楚的。

會踩的坑：光暈或雜訊太重會讓字變糊、毛玻璃在舊瀏覽器沒效果 → 加完把手機轉到最亮和最暗各看一次。

加完之後 回 STEP 3 做一次驗收（按一下、按 F5、拉窄），再上傳一次檔案、留下第二個 commit。 特效壞掉的機率比你想的高，但你已經會退回上一版了。
卡住了

三個急救指令

🧸 白話說

卡住很正常，多半是沒把問題講清楚給師傅聽。這三句幫你講明白。

  1. 打不開／一片空白
    「網頁打開是空白的，請檢查 index.html 是否完整，並確認所有程式碼都寫在這一個檔案裡。」
  2. 改一次就整個壞掉
    「請退回上一個可以正常運作的版本，然後只做這一件事：______」
  3. 一直說完成但就是不對
    補上「我實際看到什麼」＋「我期望看到什麼」，並要它「先告訴我問題在哪，再改」。

卡超過 90 秒就舉手，那是我和助教的工作。
